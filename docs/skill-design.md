# Skill System Design (Dev)

> **Status: Development / Experimental** — This document describes a system that is actively being designed and iterated on. Interfaces, conventions, and behaviors are subject to change.

---

## Motivation

AI coding agents are good at generating one-shot scripts, but those outputs are typically discarded after the conversation ends. The skill system aims to:

1. **Package reusable analysis logic** so it can be invoked by both users and agents without boilerplate
2. **Capture session-scoped artifacts** — charts, reports, HTML, data files — that can be referenced in later turns
3. **Hide implementation details** from both the user and the model, so the interface stays simple

The vision is that complex, multi-turn exploratory workflows can be expressed as:

```text
user intent + data reference + skill invocation
  => reusable analysis
  => persistent artifact
  => further refinement in subsequent turns
```

---

## Core Concepts

### Skill

A skill is a directory under `.claude/skills/` containing:

- `SKILL.md` — metadata and model-facing instructions describing when and how to invoke the skill
- `scripts/` — executable implementation (Python, shell, etc.)

The model should see only the high-level invocation via `agent-ui-skill-run`. It should never need to know the internal script paths or output directory management.

### Artifact

An artifact is any output file generated by a skill execution, stored under a session-scoped directory:

```text
<workspace>/.agent-ui/<session-id>/
```

Artifacts are recorded in a `manifest.json` with type classifications (e.g. `rich_display/html`) and can be:
- Previewed in the desktop UI
- Referenced by file path in later conversation turns
- Listed and browsed per session

### agent-ui-skill-run

The wrapper that bridges the agent and the skill:

```bash
$HOME/.agent-ui/bin/agent-ui-skill-run \
  --skill <skill-name> \
  --method <method> \
  --output-dir "$AGENT_UI_OUTPUT_DIR" \
  -- <implementation command>
```

It resolves the skill implementation, executes it, captures outputs, writes `manifest.json`, and emits a structured result block that the model can summarize.

## Example Flow: K-line Chart

### User input

```
/kline-chart @samples/kline_sample.csv  Generate an interactive chart
```

### What happens

1. The agent recognizes the `/kline-chart` slash command
2. It reads `SKILL.md` for invocation instructions
3. It runs `agent-ui-skill-run` pointing to the skill's `scripts/run.py`
4. The script reads the CSV, generates a Plotly HTML chart, and writes it to the output directory
5. `agent-ui-skill-run` records the output in `manifest.json`
6. The agent summarizes the result
7. The desktop UI displays a clickable link to the generated HTML artifact

### Result

```text
.agent-ui/<session-id>/kline-chart.xxx.html
```

The artifact can be opened in the preview panel and referenced in subsequent turns:

```
/kline-chart @samples/kline_sample.csv  Generate a chart, then add MA5 and MA20 lines
```

## Skill Design Principles

1. **Hide runtime details** — The model-facing instruction should not mention output directories, environment variables, or internal script paths.
2. **One responsibility per skill** — A skill should do one thing well (e.g. generate a chart, transform data, produce a report).
3. **Structured output** — Use `agent-ui-skill-run` so artifacts are tracked automatically.
4. **Idempotent when possible** — The same input should produce roughly the same output, making skills predictable and debuggable.

---

## Current Limitations

- Limited artifact type classification (primarily `rich_display/html`)
- No dependency management between skills
- No skill chaining / pipelining
- No versioning or caching of skill outputs
- Error handling is minimal

These are all active areas of exploration.

---

## Future Directions

- **Skill composition** — chain skills: transform data → generate chart → produce report
- **Parameterized skills** — structured inputs beyond raw file paths
- **Skill marketplace / discovery** — browse and install skills from a registry
- **Output caching** — skip re-execution when inputs haven't changed
- **Non-HTML artifacts** — native data viewer, image preview, PDF render
